# Open World Launch Implementation Plan

> **For agentic workers:** Execute this plan task-by-task. Recommended path:
> dispatch a fresh subagent per task, review each result with `review-quality`,
> then continue. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Deliver a working community where people discover and share open-source rebuilds, find collaborators, and coordinate work, with durable shared data and a documented production deployment.

**Architecture:** Preserve the React/Vite frontend and visual identity. Add a single Node service with SQLite persistence, same-origin API and cookie sessions, owner-based permissions, reporting, and admin moderation. Run one application replica behind an HTTPS reverse proxy, keeping the database on a persistent volume.

**Tech Stack:** React 19, Vite 6, Node 24+, Express, SQLite, Node crypto, Node test runner, Docker Compose.

## Scope and decisions

Launch includes accounts, password recovery via a one-time recovery key, profiles, project CRUD, discovery/filtering/sorting, bookmarking, membership, project discussions, reporting, moderation, account deletion, privacy/terms/community pages, shareable URLs, metadata, persistent deployment, backups, and meaningful API/browser tests. No third-party credentials are required for local operation. Email delivery and social sign-in are optional future integrations. The first release does not scrape third-party repositories or claim project affiliations. No invented community members or activity metrics appear in production.

The user authorized unattended implementation until ready for launch or a true roadblock. Build deployment artifacts and verify locally; do not guess a public domain or modify shared homelab infrastructure without a concrete destination. Keep a deployment decision as the final external step if none is available.

## Acceptance checks

The site is application-ready when two independent accounts can share and coordinate projects using one durable API; only authorized owners/admins can modify content; anonymous users can browse safely; account recovery and deletion work; admin can respond to reports; all routes and mobile layout work; no demo content is misrepresented; production package, backup/restore and operational instructions are verified. Public launch additionally requires a selected HTTPS domain, persistent hosting, a real administrator, and a backup destination. These external values must be supplied or discovered from explicit project configuration.

## Rollback

Back up the database before deployment changes. Preserve previous image and matching database snapshot. Avoid restoring a schema snapshot over newer writes; stop the app and restore the selected complete backup only during a deliberate rollback. Current prototype files are uncommitted user-authorized work and must be preserved through implementation history.

## Execution record

The ordered implementation is complete. API contracts were extended with administrator-only report context and public operator/contact metadata. Independent reviews found session-read throttling, credential-route alias throttling, whitespace-only password acceptance, missing discussion report context, hidden-parent message moderation, recovery history handling, and stale project reads; the findings were fixed and regression checks added where applicable.

See `docs/LAUNCH-STATUS.md` for exact final test counts, browser checks, production packaging evidence and the external deployment boundary. No public domain, server or backup destination is configured. The prototype’s fabricated accounts and activity were replaced by shared server data; development QA accounts are removed after verification.
